# Netty 服务器粘包拆包测试指南

## 概述

本指南将帮助您测试 Netty 服务器的粘包拆包处理能力。您的服务器已经实现了基于长度字段的帧解码器来处理这些问题。

## 协议格式

```
起始标志(1B) + 数据长度(1B) + 序列号(2B) + flag(1B) + 帧类型(1B) + 消息体 + CRC(2B)
```

- **起始标志**: `0x68` (1 字节)
- **数据长度**: 序列号(2) + flag(1) + 帧类型(1) + 消息体长度 (1 字节)
- **序列号**: 消息序列号 (2 字节)
- **flag**: 标志位 (1 字节)
- **帧类型**: 消息类型 (1 字节)
- **消息体**: 实际数据内容 (可变长度，最大 200 字节)
- **CRC**: 校验码 (2 字节)

## 测试方法

### 方法 1: 使用 Shell 脚本测试

1. **启动服务器**:

   ```bash
   mvn clean compile exec:java -Dexec.mainClass="com.sailfish.server.listener.NettyServer"
   ```

2. **运行测试脚本**:

   ```bash
   chmod +x src/main/resources/test_server.sh
   ./src/main/resources/test_server.sh localhost 8080
   ```

3. **分析日志**:
   ```bash
   chmod +x src/main/resources/analyze_log.sh
   ./src/main/resources/analyze_log.sh
   ```

### 方法 2: 使用 Java 客户端测试

1. **启动服务器** (同上)

2. **运行 Java 测试客户端**:
   ```bash
   mvn exec:java -Dexec.mainClass="com.sailfish.server.listener.TestClient"
   ```

## 测试场景

### 1. 快速连续发送测试

- **目的**: 测试粘包处理能力
- **方法**: 快速发送 100 个消息，无延迟
- **预期**: 服务器应正确解析每个消息

### 2. 带延迟发送测试

- **目的**: 测试正常情况下的消息处理
- **方法**: 发送 100 个消息，每次间隔 10ms
- **预期**: 消息按顺序正确解析

### 3. 不同长度消息测试

- **目的**: 测试拆包处理能力
- **方法**: 发送短消息和长消息交替
- **预期**: 所有消息都能正确解析

### 4. 大量数据测试

- **目的**: 测试缓冲区处理能力
- **方法**: 发送接近最大长度的消息
- **预期**: 消息正确解析，无溢出

### 5. 边界测试

- **目的**: 测试最大长度限制
- **方法**: 发送最大长度(200 字节)的消息
- **预期**: 消息正确处理

### 6. 异常数据测试

- **目的**: 测试容错能力
- **方法**: 发送不完整、格式错误的数据
- **预期**: 服务器应优雅处理异常

## 检查要点

### 1. 日志分析

检查以下日志信息：

- 连接建立和断开事件
- 消息解码记录
- 异常信息
- 序列号连续性

### 2. 粘包检测

- 检查是否有消息丢失
- 检查序列号是否连续
- 检查消息内容是否正确

### 3. 拆包检测

- 检查消息长度字段是否正确
- 检查消息体是否完整
- 检查是否有不完整的解析记录

### 4. 性能检查

- 检查处理时间
- 检查内存使用
- 检查 CPU 使用率

## 常见问题及解决方案

### 1. 消息丢失

**现象**: 发送的消息数量与接收的不匹配
**可能原因**:

- 粘包处理不当
- 缓冲区溢出
- 网络问题

**解决方案**:

- 检查 `CustomLengthFieldFrameDecoder` 配置
- 增加缓冲区大小
- 添加重传机制

### 2. 消息重复

**现象**: 同一消息被处理多次
**可能原因**:

- 拆包处理不当
- 长度字段解析错误

**解决方案**:

- 检查长度字段计算
- 添加消息去重机制

### 3. 服务器崩溃

**现象**: 服务器在处理大量消息时崩溃
**可能原因**:

- 内存泄漏
- 异常处理不当
- 线程池耗尽

**解决方案**:

- 检查内存使用
- 完善异常处理
- 调整线程池配置

## 优化建议

### 1. 协议优化

- 添加消息 ID 用于去重
- 添加时间戳用于排序
- 优化 CRC 算法

### 2. 性能优化

- 使用对象池减少 GC
- 批量处理消息
- 异步处理非关键操作

### 3. 监控优化

- 添加性能指标
- 实时监控连接数
- 告警机制
